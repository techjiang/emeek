## 产物体积

| 指标 | 实测 | Phase 1 目标 |
| --- | --- | --- |
| 单个 HTML（含内联 CSS/JS） | 17–23 KB | < 50 KB |
| 构建产出的 JS 文件 | 0 个 | < 30 KB (gzip) |
| 外部网络请求 | 0 个 | — |
| 3 篇文章的完整站点 | 206 KB / 16 个文件 | — |

**没有独立的 JS 文件**：主题脚本内联在 HTML 里，约 6 KB 未压缩。它负责主题切换、
阅读进度、目录高亮、代码复制与搜索 —— 全部延迟到 `</body>` 前，TBT 仍为 0–20 ms。

## 这些数字是怎么来的

不是靠事后优化，是设计约束倒推出来的：

1. **零外部请求** —— 没有字体、没有 CDN、没有分析脚本。用系统字体栈，
   代价是放弃品牌字体，换来的是首屏没有 FOUT/FOIT。
2. **关键 CSS 内联** —— 主题 CSS 约 9 KB，一个 RTT 的收益大于缓存收益。
   超过 24 KB 时自动退回外链（见 `output.js`）。
3. **高亮在构建期完成** —— 浏览器不下载语法定义，`<span class="tok-*">` 直接躺在 HTML 里。
4. **脚本默认不阻塞** —— 交互逻辑（主题切换、阅读进度、搜索）全部延迟到 `</body>` 前，
   且在 `IntersectionObserver` / 事件回调里才真正干活。

## 满分不是一次到手的

第一轮实测时，Best Practices 96、Accessibility 95，扣分项都是真实问题：

- **缺 favicon** → 触发一次 404 请求，控制台报错
- **正文链接只靠颜色区分** → 色觉障碍用户无法识别，改为下划线
- **代码块语言标签与注释对比度不足** → 浅色底上只有 3.6:1，加深一档到 4.5:1
- **任务列表复选框没有可访问名称** → 补 `aria-label`

这些都不是「为了分数」的调整，是本来就应该修的问题。

## 复现方式

```bash
node scripts/lighthouse.mjs
```

脚本会构建 `examples/minimal`、起一个本地静态服务器、逐页跑 Lighthouse，
并打印 Markdown 表格。


## Studio 客户端体积（S2-3b 复测）

门禁 600KB，S2-3b 结束时 **350KB 入口 + 38 个按需 chunk（共 1677KB）**。

| 阶段 | 入口 |
| --- | --- |
| S2-3a | 311KB |
| S2-3b | **350KB**（+39KB / +12.5%） |

涨幅构成，逐项都有理由：

| 新增 | 大约 | 为什么必须在首屏 |
| --- | --- | --- |
| URL / HTML 消毒（sanitize-url + sanitize-html） | ~6KB | 预览渲染每次输入都会走它 —— 懒加载等于「预览第一次渲染还是能注入」 |
| Key 状态机 + 输出面消毒（keyring） | ~7KB | 面板一打开就要显示状态，而 `redact` 是日志出口的一部分 |
| 快捷键声明表 + F1 渲染（shortcuts） | ~9KB | F1 表是声明面，按住就能弹是它唯一的用法 |
| 落盘时机 + 移动端布局（drafts/client 增量） | ~6KB | `visibilitychange` 必须在页面隐藏的那一瞬就绪，不能等懒加载 |
| 热更新同步（sync） | ~5KB | SSE 要尽早连上，否则开页面头几秒的磁盘改动会漏 |
| 其余（diff） | ~6KB | |

**没有选「懒加载它们换首屏」**：这五项各自的触发时机都在用户第一次交互之前
或之上的瞬间（隐藏、渲染、连通道），懒加载会把它们的生效时间推迟到
「已经被需要之后」。39KB 换的是「这些防线从第一帧起就是活的」。

chunk 数（38）与总大小（1677KB）不变 —— 说明语言语法仍然是按需的，
这次涨的全在入口。
