# D5 · 快捷键帮助表是声明面

**状态**：已确认（S2-3b 落地）
**日期**：2024

## 背景：Ctrl+G 是一个 bug，但这不是「一个 bug」

F1 表里写着 `Ctrl+G` 跳转到行，实际按下去没有反应 —— 因为根本没有 handler。
修掉这个 bug 只值五分钟，真正的问题是**这类不一致会不断发生**：
帮助表是手写的静态 HTML，handler 是另一处代码，两者之间没有任何机制保证一致。

「说了就得有」是硬约束，所以声明面不能被当成文档，它得**被测试盯着**。

## 决策

**双向核对，两个方向都报红。**

```
F1 表里的每一条  → 必须有真实 handler，且按下真触发
handler 里的每一条 → 必须在 F1 表里有条目
```

- 表里有、实现没有 → 红（这是 Ctrl+G）
- 实现有、表里没有 → 红（用户永远不知道有这个键位）

声明数据只留**一份**：`packages/editor/src/studio/shortcuts.js`。
F1 对话框从这份数据渲染，handler 绑定也从这份数据读，审计测试还是读这份数据。
手写 HTML 的那份删掉 —— 两份声明必然分叉。

三层验证，缺一层都会漏：

| 层 | 抓什么 |
| --- | --- |
| 声明 ↔ 实现注册表 | Ctrl+G 这类「表里有实现没有」 |
| 声明 ↔ 命令表 | 工具栏 tooltip 与 F1 表说的是不是同一套键位 |
| 真实按键 → 真实 handler | 声明了但按键被别的监听器截胡（抢键） |

第三层必须真浏览器：Node 里模拟 keydown 测不出「CodeMirror 先吃掉了这个键」。

触屏没有功能键。移动端必须提供等价入口（工具栏 / 命令面板），
并且**在表里如实标注**哪些键位在触屏上不可用 —— 不标注等于假装可用。

## 进 CI

`pnpm check:shortcuts` 进 CI 门禁。任何一处不一致直接失败，
不给人「先合进去、回头再补」的窗口 —— 那个窗口就是 Ctrl+G 出现的地方。

## 这一条的要害

把「修一个 bug」变成「这类 bug 无法再发生」。
差别在于：前者靠人记得检查，后者靠门禁不让它过。
