# 为什么我们还需要一个静态博客引擎

市面上的静态站点生成器足够多了。Emeek 不打算在功能清单上再赢一次。

它只想解决一件事：**让「写」和「发布」之间的摩擦降到接近于零。**

## 摩擦在哪

传统的博客系统里，写一篇文章要经历：

1. 打开编辑器或后台
2. 想标题、选分类、填标签、写摘要
3. 预览、调整格式
4. 发布

而 Gmeek 那一派的做法把第 1、2、3 步压缩成了一件事 —— 在 GitHub 上开一个 Issue。

## Emeek 继承了什么

- **内容即 Issue**：Markdown 即内容，GitHub 即 CMS
- **构建即 Actions**：不需要本地环境
- **部署即 Pages**：零服务器、零运维、零成本

这三根支柱不动摇，是 Emeek 的第一原则。

## Emeek 想多做什么

性能。是那种可以量化的性能，而不是一句「很快」。

| 指标 | 目标 |
| ---- | ---- |
| Lighthouse Performance | ≥ 95 |
| 首屏 HTML | < 50KB |
| JS Bundle（Gzip） | < 30KB |
| 外部请求 | 0 |

> 宁可少一个功能，不让页面慢 100ms。

为了做到这一点，Emeek 的默认主题不加载任何外部字体、不引入前端框架，
样式表小到可以直接内联进 `<head>` —— 首屏只有一次请求。
